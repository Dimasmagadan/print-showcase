# Анимации: как устроены и куда добавить ещё

Дата: 2026-10-25. Вопрос: как сделана анимация в херо главной и на странице robot-cat, и есть ли другие страницы, куда можно добавить такую же.

---

## 1. Как устроены текущие анимации

На сайте три независимых механики + одна дев-эксперименталка.

### 1.1. Главная — hero scroll-сцена (home-motion)

Слоёная сцена «принтер → кот внутри → мастерская с настоящим котом», проигрываемая скроллом.

| Часть | Файл |
|---|---|
| Разметка и CSS слоёв | `src/components/HomeHero.astro` |
| Inline-гейт в `<head>` (класс до первой отрисовки) | `src/components/HomeMotionHead.astro` |
| Скролл-контроллер (rAF → CSS-переменные) | `src/scripts/home-motion.ts` |
| Чистая функция прогресса (без DOM) | `src/scripts/home-motion-state.ts` |
| Какая модель + какой медиа-комплект | `src/home-featured.ts`, `src/home-featured-media.ts` |

Механика:

- Секция `.home-story` растягивается до `300svh`, стейдж внутри — `position: sticky; top: 0`. Скролл — единственные «часы», никакого JS-скролла.
- Слои сцены (принтер, дверца крупным планом, фото мастерской, кот через SVG-маску, блик на стекле) позиционируются/масштабируются/проявляются **CSS-переменными** (`--cat-height`, `--printer-scale`, `--workshop-opacity`, `--reflection`…). JS на скролле только пишет переменные через rAF — layout-чтений на скролле нет, анимируются только composite-свойства.
- Класс `home-motion` ставит inline-скрипт в `<head>` **до первой отрисовки**, чтобы страница не прыгала. Условия жёсткие: достаточное окно, нет `prefers-reduced-motion`, поддержка `ResizeObserver`/`img.decode`/`inert`/`svh`, нет `location.hash`, не back/forward без сохранённого состояния.
- Деградация многослойная: ошибка декода слоя → `data-failed` и запасная статичная картинка; не влез текст или узкое окно → отключение с сохранением позиции каталога; без JS — статичный херо. Сцена включается только если модель-герой опубликована и есть проверенный медиа-комплект, иначе — обычный статичный херо.
- Спека и отчёт: `docs/design/home-motion/`.

### 1.2. Robot-cat — canvas scroll-история

Один sticky-стейдж K0–K7: 85 кадров 1600×1000 рисуются на `<canvas>` по прогрессу скролла, тексты эпизодов — обычный HTML поверх.

| Часть | Файл |
|---|---|
| Разметка эпизодов, постеры, аннотации | `src/components/RobotCatStory.astro` |
| Рантайм единого стейджа | `src/scripts/robot-cat-redesign.ts` |
| Состояние (прогресс → кадр/копия) | `src/scripts/robot-cat-redesign-state.ts` |
| Пул ImageBitmap | `src/scripts/robot-cat-redesign-pool.ts` |
| Кадры (WebP) и манифест | `public/media/robot-cat-story/v2/`, рецепты `scripts/robot-cat-story-*.py` |
| Тексты истории | `src/content/robot-cat-story.ts` + anchors JSON |

Механика:

- Постеры K0–K7 (десктоп + мобильные) — это и контент, и фолбэк: без JS или при сбое страницы остаются читаемыми.
- Рантайм по скроллу выбирает кадр из манифеста и рисует в canvas; пул держит **≤8 декодированных bitmap и ≤3 одновременных запроса**, подгружает соседние кадры вперёд/назад по направлению скролла, чистит всё при уходе сцены из вьюпорта и на `pagehide`.
- Включение: `motionEligible()` — размер окна, не reduced-motion; плюс `fits()` проверяет, что тексты эпизодов влезают, иначе принудительная статика (`data-static-reason`).
- Хэш-навигация `#robot-key-0…7`, фокус и скролл-якоря сохраняются и в статичном режиме.
- Спека и отчёт: `docs/design/robot-cat-redesign/`, `docs/design/robot-cat-story/`.

### 1.3. Все страницы — cross-document View Transitions

Подключены один раз в `src/layouts/Base.astro` (`InternalMotionHead.astro` + `internal-motion.ts`): картинка и название карточки каталога (или финальной подписи херо) перелетают в обложку и H1 страницы модели. Работает автоматически для любой новой страницы модели — новым страницам ничего добавлять не нужно, достаточно ссылок с `data-model-id`/`data-motion-source`. Спека: `docs/design/internal-motion/`.

### 1.4. Дев-only: ambient-фоны (не опубликованы)

`src/pages/robot-cat-backgrounds/[variant].astro` + `RobotCatBackground.astro` + `src/styles/robot-cat-backgrounds.css` — четыре варианта фона (studio/aurora/blueprint/orbits) на чистых CSS-анимациях: цветовой wash, орбиты, сетка, зерно; кнопка «Пауза», reduced-motion отключает. В прод не собирается (`getStaticPaths` возвращает `[]` вне dev) и закрыт `noindex`. Это лаборатория, а не страница сайта.

| Страница | Сколько | Анимация сейчас |
|---|---|---|
| `/` главная | 1 | hero scroll-сцена + View Transitions |
| `/models/robot-cat/` | 1 | canvas-история K0–K7 + View Transitions |

## 3. Что есть у моделей для анимации

Полноценная scroll-история требует **комплета кадров** (у robot-cat — 85 кадров из рендеров соседнего репо по рецептам). Что фактически лежит:

- **animal-puzzle** — 7 рендеров, включая пары «разобранная / собранная» (assembled_angle + exploded_angle, top-варианты) и «лоток пустой / заполненный». Двухкадровый сюжет уже возможен без новых ассетов.
- **bunny-meds, letters-blocks, med-box** — по 2 живых фото + 2–3 рендера. Хватает на мини-историю «рендер → настоящее фото» (паттерн финала home-сцены).
- **teeth-box** — только 2 рендера, фото нет. Анимировать пока нечего: сначала фото печати (их и так ждём по CLAUDE.md).
- Видео нет ни у одной модели.

## 4. Куда можно добавить (по убыванию выгоды/цен)

### 4.1. Страницы остальных моделей — мини-история «рендер → живое фото» ⭐ рекомендую

Самое дешёвое повторение существующего языка анимации. Схема как в финале home-сцены: два слоя (рендер и фото), прозрачность верхнего привязана к скроллу/входу в вьюпорт. Не нужны ни canvas, ни пулы, ни манифесты. Технически два пути:

- чистый CSS `animation-timeline: view()` — прогрессивное улучшение, Firefox/Safari просто покажут рендер (идея уже описана в REVIEW.md, п. E);
- либо тот же паттерн `IntersectionObserver`/rAF + CSS-переменная, что в `home-motion.ts`, если нужна кросс-браузерность.

Кандидаты: **animal-puzzle** (вместо фото — кроссфейд «разобранная → собранная» из готовых рендеров, это ещё и демонстрация конструкции), **bunny-meds** (медкормушка: рендер → фото с настоящим кроликом — самый человечный сюжет), **letters-blocks** и **med-box** (рендер → фото).

### 4.2. Robot-cat: промоутить ambient-фон из дев-эксперименталки ⭐ рекомендую

Не новая страница, а перенос готовой механики в прод: один выбранный вариант (studio или aurora, приглушённый) на страницу `/models/robot-cat/`. Всё уже написано и проверено в браузере (REVIEW.md, п. A): `mix-blend-mode: lighten` поверх запечённой подложки, пауза, reduced-motion; для статичного фолбэка — тот же фон неподвижным градиентом. Требуется только решение пользователя и приглушение насыщенности.

### 4.3. 404-страница (новая) — ambient-фон почти бесплатно

Страницы 404 нет. Если завести (GitHub Pages легко через `public/404.html` или Astro), то она — идеальное место для CSS-only анимации: кот + фон из `RobotCatBackground` без тяжёлых ассетов, с кнопкой «Все модели». Здесь дешёвая декоративная анимация уместна как нигде — страница утилитарная, контента нет.

### 4.4. Каталог на главной — лёгкий стаггер, не scroll-история

Контраст «кинематографичная сцена → статичная сетка» сглаживается каскадным появлением карточек (IntersectionObserver, `translateY` + opacity, стаггер 60–80 мс) и hover-подъёмом с тенью. Полная scroll-история каталогу не нужна — иерархия wow: сцена > переходы > каталог (REVIEW.md, п. B и «чего не делать»).

### 4.5. Полные canvas-истории для других моделей — возможно, но дорого

Механика переиспользуема (`robot-cat-redesign-pool.ts` почти не привязан к robot-cat), но для каждой модели нужны: комплект кадров по рецептам (`scripts/robot-cat-story-*.py`), тексты истории, анкеры аннотаций и генерализация `RobotCatStory.astro` (сейчас он жёстко привязан к контенту robot-cat: `src/content/robot-cat-story.ts`, JSON-анкеры, тексты в компоненте). Это отдельный проект на модель. Имеет смысл только если пользователь захочет «вторую robot-cat» — например, для animal-puzzle, у которого достаточно рендеров для нарезки кадров.

### 4.6. Sticky-херо (паттерн home-motion) на другие страницы — не рекомендую

Паттерн требует уникального медиа-комплекта на каждую сцену: слои, SVG-маска кота, анкеры позиций, запасные кадры. Это самый дорогой формат; robot-cat уже получил свою историю, остальным моделям достаточно кроссфейда из 4.1.

## 5. Ограничения и правила для любой новой анимации

Сложившийся в проекте контракт (нарушать нельзя — на нём держится приёмка):

1. **Статика по умолчанию, анимация — надстройка.** Без JS, на старых браузерах и при сбое ассетов контент полон и читаем.
2. **Гейты до отрисовки или до активации:** `prefers-reduced-motion`, размер вьюпорта, feature detection, отключение на resize/неудачном фите.
3. **Бюджеты:** ≤3 одновременных запроса, ≤8 bitmap, WebP, ленивое включение по близости к вьюпорту, полная очистка на `pagehide`/уходе из вьюпорта.
4. **rAF-throttle**, на скролле — только запись composite-свойств (CSS-переменные), без layout-чтений.
5. **Иерархия wow:** hero-сцена и истории моделей остаются вершиной; каталог и утилитарные страницы — не громче.
6. Из CLAUDE.md: что публиковать — решает пользователь; новые тексты вычитываются до пуша; браузерная матрица (Safari/Firefox) для новых анимаций обязательна до публикации.
