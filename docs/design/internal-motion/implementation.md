# Внутренние переходы: рабочий прототип

23 октября 2026. Реализация и визуальная приёмка **не завершены**.

**Текущий режим: проверки возвращены; картинка и заголовок карточки — два общих элемента нативного View Transition.**
Последняя просьба пользователя заменяет прежнее появление заголовка целиком:
теперь span внутри h3 карточки переходит в span внутри H1 модели.
Имена model-ID и model-title-ID назначаются только выбранной паре.
Обе группы движутся за 360 мс; текстовые snapshots вписываются с сохранением
пропорций и учитывают переносы в итоговой вёрстке. Общее завершение до 420 мс.
Все шесть опубликованных карточек используют общий шаблон.

Вернулись пороги 1280×800, reduced motion, проверки маршрута/истории/якорей,
ID, ассета и готовности медиа. При неготовом изображении — fade, при этом
пара названия остаётся общей. Новый ввод/resize завершает эффект;
scroll/focus учитываются после transition.ready, чтобы обычные стартовые
события браузера не отменяли переход до первого кадра. Запросы медиа
не задерживают навигацию. Временный безусловный preview больше не активен.

## Механизм

Нативные cross-document View Transitions, обычные HTML-документы Astro,
без ClientRouter и зависимостей. Настоящие href и жизненный цикл документа
сохраняются. Поддержка механизма: Chromium 126+, Safari 18.2+;
в остальных браузерах — обычная навигация. Это сведения документации,
а не результат прогона браузерной матрицы.

- https://developer.chrome.com/docs/web-platform/view-transitions/cross-document
- https://docs.astro.build/en/guides/view-transitions/
- https://view-transitions.chrome.dev/

Добавлен пространственный прототип: snapshot полного изображения
сохраняет его пропорции, а clip-path отдельно раскрывает кадрирование.
Начальная геометрия учитывает реальный hover-transform. Общий элемент
получает имя model-ID только у выбранной пары. Прозрачные поля и белая
подложка карточки отделены от изображения; скругление не добавляется
внутри свободных полей contain. Название карточки и изображение перемещаются к H1 и обложке за 360 мс. Отдельный вход из hero сохраняет появление группы заголовка за 140–420 мс.

Ссылка определяется фактическим click, а не поиском первого совпадения
href: карточка и hero одного кота теперь различаются. Одноразовый пакет
в sessionStorage проверяется по URL источника/цели, ключу исходной записи,
ID и сроку 15 секунд; прямой вход его не использует. Hero использует
перекрытие композиции за 280 мс и отдельный заголовок. При несовпадающем
asset ID или геометрии — fallback прозрачностью за 180 мс.

Декоративная копия не имеет ссылки, alt пуст, aria-hidden=true,
pointer-events:none. Временный DOM очищается после capture/finished,
при отмене и возвращении из bfcache. Никакой галерейный full не декодируется
заранее. Decode обложки выполняется по возможности во время парсинга;
если он не успел до pagereveal, используется короткий fallback прозрачностью без ожидания медиа.

Пространственный прототип и связка hero **не проверены визуально**.
Эту версию нельзя считать выполнением всей спецификации.

Эффекты ограничены 1280×800 и no-preference. История и якоря пропускают
эффекты; resize, scroll, focus, клавиатура и pointerdown завершают их.
Базовый HTML видим без JS. При неготовой обложке или шрифте эффект
пропускается, навигация не ждёт decode или галерею.

## История

history.replaceState сохраняет homeReturn на исходной записи истории:
ID модели, карточка/hero, режим, положение карточки, прогресс, способ ввода.
Новая загрузка по истории резервирует геометрию сцены в head, затем
восстанавливает относительное положение после готовности медиа.
При недоступной сцене целевой точкой становится соответствующая карточка.
bfcache сохраняет штатную позицию; исключение — исчезнувший hero при
сменившемся режиме, тогда восстанавливается карточка. Поведение требует
браузерной проверки. Новое действие пользователя отменяет отложенное
восстановление при загрузке медиа.

«Все модели» теперь ведёт в #models с BASE_URL. Галерея явно возвращает
фокус на открывшую кнопку при close, включая Escape.

## Исправление после локальной проверки пользователя

Пользователь сообщил, что переход не виден. Найден дефект readiness:
контроллер отменял весь эффект, если pagereveal приходил до завершения
асинхронного decode или загрузки шрифта. Теперь этот порядок событий
сохраняет native fade 180 мс, а пространственный режим требует готовой
обложки. Отдельный старый snapshot в fallback остаётся обрезанным и
исчезает синхронно со старой страницей, без показа полного uncropped фото.

В head модели добавлен rel=expect/blocking=render до #model-cover:
он ждёт только парсинга первого экрана, не загрузки изображения или галереи.
Регрессионный harness явно вызывает pagereveal до DOMContentLoaded и
при loading шрифта. Сервер :4323 проверен HTTP: отдаёт исправленную функцию
fadeFallback и маркер model-cover. Это проверка отдачи кода, не доказательство
отрисовки: подключённый браузер всё ещё отсутствует.
