## 1. Задача и границы

Превратить главную в визуальную витрину авторских 3D-печатных вещей:
hero представляет автора и его печать через текст и фотографию принтера;
проекты доступны сразу под ним.
Передать композицию и плотность референса, адаптировав их к четырём проектам.

В первую версию входят:

1. Общая фиксированная тёмная палитра и типографика.
2. Компактная шапка.
3. Статический hero с текстом о работе и фотографией принтера.
4. Одна секция «Все модели» с четырьмя карточками.
5. Адаптивность и состояния взаимодействия.
6. Проверка страниц моделей после изменения общих стилей.

Не входят: магазин, заказы, корзина, аккаунт, поиск, рейтинги, переключатель темы,
новые модели, 3D-вьюер, скачивание STL/3MF, автопрокрутка hero.
Не переносить из референса «Play», настройки, оценки, жанры и сериальные метаданные.
Не создавать «Рекомендуем вам» без реальной логики рекомендаций.
Не повторять четыре модели в нескольких искусственных подборках.

Сохранить русский язык, текущие URL, тексты историй, галерею, видео,
OG-изображения, Telegram и скрытие контакта при пустом `SITE.contact`.
Не публиковать изменения в рамках локальной реализации: push в main запускает
GitHub Pages; новые тексты должны быть вычитаны пользователем согласно CLAUDE.md.

## 3. Композиция

### Структура без оформления

```text
Шапка: Print Showcase | Модели | Telegram

Hero:
  метка «АВТОРСКАЯ 3D-ПЕЧАТЬ»
  Придумываю и печатаю вещи         крупная фотография принтера
  краткий рассказ о работе
  [Смотреть модели] [Telegram-канал]

Все модели                         4 проекта
  изображение  изображение  изображение  изображение
  название     название     название     название
  метаданные   метаданные   метаданные   метаданные

Подвал: Print Showcase · Telegram
```

Основной вариант: текст слева, крупный принтер справа, изображение и фон
соединены затемнениями. Это ближе всего к референсу.

Альтернативы для обсуждения:

- Полноэкранное фото с текстом поверх: ближе к киноафише, но нужен подходящий
  широкий кадр со свободной левой частью.
- Изолированный принтер на тёмном фоне: лучше контролируется композиция,
  но потребуется подготовка реальной фотографии принтера.

Для реализации использовать основной вариант с фотографией принтера пользователя.
В репозитории подходящего фото пока нет: это единственный недостающий визуальный материал.
Если изображение не удаётся вписать без заметного прямоугольника, сначала
показать этот результат и решить вопрос с ассетом; не маскировать проблему
сильным размытием или затемнением самого предмета.

### Размеры

Ширины проверки: 360, 390, 768, 1024, 1440 и 1920 px.

| Параметр | <768 px | 768–1023 px | ≥1024 px |
| --- | --- | --- | --- |
| Боковые поля | 20 px | 32 px | 48 px |
| Максимальная ширина контента | 1440 px, включая поля | та же | та же |
| Шапка | минимум 64 px | 64 px | 72 px |
| Hero | высота по контенту | высота по контенту | минимум 500 px после шапки |
| Текст hero | вся ширина | вся ширина, max 560 px | около 44%, max 560 px |
| Изображение hero | сверху, высота 280–340 px | сверху, 360 px | справа, около 60% |
| Отступ до заголовка каталога | 32 px | 40 px | 40 px |

На десктопе hero не занимает весь экран. При 1440×900 должны быть видны
заголовок секции, изображения и названия первого ряда карточек.
Не добавлять пустую полосу, аналогичную промежутку под «Recommended» в референсе.

На мобильном: шапка → изображение → текст hero → кнопки → каталог.
Не накладывать длинный заголовок на предмет и не задавать фиксированную высоту
всему hero. Обеспечить корректный рост при увеличении текста.

## 4. Палитра и типографика

Значения подобраны визуально по референсу, а не извлечены пипеткой.
Тема всегда тёмная независимо от системных настроек.

| Токен | Значение | Использование |
| --- | --- | --- |
| `--bg` | `#0D0D12` | Основной фон |
| `--surface` | `#18191F` | Панели и резервный фон изображений |
| `--surface-raised` | `#272830` | Вторичная кнопка |
| `--ink` | `#F5F5F7` | Заголовки и основной текст |
| `--muted` | `#B0B1BB` | Метаданные и вторичный текст |
| `--line` | `#30313A` | Разделители |
| `--accent` | `#FFBC36` | Логотип, главный CTA, фокус |
| `--accent-hover` | `#FFD06B` | Hover главной кнопки |
| `--accent-ink` | `#17130A` | Текст на жёлтом |

Прописать `color-scheme: dark`; удалить переопределение палитры через
`prefers-color-scheme`. Не делать акцент оранжевым и не добавлять фиолетовые
свечения, стеклянные панели и декоративные градиенты.
Градиенты используются только для стыковки изображения hero с фоном.

Шрифт: Inter для текста и заголовков. Убрать Unbounded, поскольку его широкие
буквы меняют характер референса и растягивают русские названия.
Загружать только используемые начертания 400, 500, 600, 700, 800; сохранить
системный fallback. Не менять способ загрузки шрифта без необходимости.

| Элемент | Desktop | Mobile |
| --- | --- | --- |
| Логотип | 20 px / 800 | 18 px / 800 |
| H1 | 48 px / 1.08 / 800 | 32 px / 1.12 / 800 |
| Заголовок секции | 22 px / 1.25 / 700 | 20 px / 1.25 / 700 |
| Описание hero | 16 px / 1.55 / 400 | 15 px / 1.55 / 400 |
| Название карточки | 16 px / 1.35 / 600 | 15 px / 1.35 / 600 |
| Метаданные | 13 px / 1.5 / 400 | те же |
| Верхняя метка | 11 px / 1.4 / 700, uppercase | та же |

H1: tracking −0.025em; не задавать фиксированное число строк с обрезкой.
Шкала расстояний: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64 px.
Радиусы: кнопки 6 px, изображения карточек 8 px, внутренние панели 10 px.
Убрать pill-форму главных кнопок. Тени у карточек не нужны.

Перед написанием компонентов перенести эти значения в `design-tokens.md`
в корне и CSS custom properties; не дублировать разные палитры по компонентам.

## 5. Шапка

- Слева `Print Showcase`, жёлтый, ссылка на `BASE_URL`.
- Рядом «Модели» → `${BASE_URL}#models`; «Telegram» → `SITE.channel`.
- У текущего пункта допустима тонкая жёлтая линия; не показывать ложное
  активное состояние на странице отдельной модели.
- На главной шапка визуально составляет одно целое с hero: без нижней границы,
  на фоне страницы. Саму шапку оставить в нормальном потоке.
- Не делать её фиксированной и не добавлять блюр.
- На страницах модели оставить обычную шапку с ненавязчивой нижней границей.
- При 360 px логотип и навигация должны помещаться. Если появился контакт
  или текст увеличен — разрешить перенос, высота шапки растёт.
- Не добавлять меню-гамбургер для двух ссылок.
- `SITE.contact` остаётся условной ссылкой, без пустых href и заглушек.

## 6. Hero: данные, изображение, действия

Hero не привязан к конкретной модели и не меняется при добавлении проектов.
Никакого featured ID, сортировки hero или дополнительных полей в коллекции.

Предлагаемый текст (нужна вычитка перед публикацией):

```text
АВТОРСКАЯ 3D-ПЕЧАТЬ

Придумываю
и печатаю вещи

Модели, которые я придумал, смоделировал и напечатал на 3D-принтере.
Здесь — как появилась каждая: идея, моделирование, печать и что пошло не так.

[Смотреть модели]  [Telegram-канал]
```

Это существующий заголовок и текст главной, уложенные в новую композицию.
Первую фразу описания брать из `SITE.description`. Перенос H1 иллюстративный:
не вставлять `<br>` для одной ширины. Не добавлять материал, габариты модели,
число напечатанных вещей и характеристики принтера без реальных данных.

**Фотография принтера — входной материал:**

- Фото пользователя; марка и модель принтера пока не заданы.
- Не подставлять случайный принтер, фото модели или сгенерированную картинку.
- Предпочтительный кадр: горизонтальный, около 16:9, ширина 2000–2400 px.
  Более маленький исходник не увеличивать искусственно.
- Принтер занимает правые 50–60% кадра; слева пространство под текст.
- Вид в три четверти, целиком узнаваемый корпус, детали рабочей зоны видны.
- Тёмное окружение, мягкий свет; без яркой стены и бытового беспорядка.
  Это пожелания к съёмке, а не основание отказываться от предоставленного фото.
- После получения фото определить безопасные `object-position` отдельно
  для desktop и mobile. Значения записать в CSS, не оставлять на случайность.
- Хранить обработанный файл в `src/assets/hero/printer.webp`, импортировать
  через Astro assets. Перед размещением удалить EXIF/геометку проверенным
  способом; не менять модельный скрипт импорта ради одного hero-фото.
- Сохранить геометрию, реальные цвета и надписи на принтере. Не дорисовывать
  вымышленные характеристики и не использовать фильтры изменения цвета.
- Не показывать лица, адреса, телефоны и другие личные детали на фоне.
- Alt: «3D-принтер в домашней мастерской» — только если соответствует фото;
  уточнить по реальному изображению, не выдумывать марку.

**Композиция изображения:**

На desktop изображение занимает правую часть hero и может заходить под текст
слева. Использовать `object-fit: cover` только если корпус остаётся целым;
иначе contain и плавное сопряжение краёв с тёмным фоном.
Начальные ориентиры для горизонтального затемнения: фон непрозрачен до 28%,
около 85% непрозрачности в 42%, около 20% в 65%, прозрачный правый край.
Снизу добавить переход в `--bg` на последних 25% высоты.
Подстроить градиент по реальному кадру: это отправные значения, не гарантия
читаемости. Принтер должен оставаться хорошо различимым.

Слои градиента имеют `pointer-events: none`; текст и кнопки выше них.
Без рамки, белой подложки и скруглённой отдельной «карточки» вокруг hero-фото.
На мобильном изображение выше текста; оставить только мягкое нижнее затемнение.
Не применять desktop-маску, которая скроет половину принтера.

До получения фотографии можно реализовать локальный каркас с однотонной
областью изображения, без broken image и случайной заглушки. Такой hero
не считать визуально законченным и не публиковать как финальную версию.

**Кнопки:**

- «Смотреть модели» → `#models`, жёлтая.
- «Telegram-канал» → `SITE.channel`, тёмно-серая; скрыть, если ссылка пустая.
- Внешняя ссылка использует `target="_blank" rel="noopener"` как сейчас.
- Высота минимум 44 px, padding 12×20 px, промежуток 12 px.
- На узком экране перенос в две строки допустим.
- Использовать `<a>`, а не кнопки с JS-навигацией.
- В первой версии нет слайдера, точек, полос прогресса и стрелок hero.
- Пустая коллекция не влияет на hero: ниже показывается empty state,
  CTA «Смотреть модели» ведёт к этой секции.

## 7. Карточки и каталог

Заголовок «Все модели», справа фактическое число проектов с корректным
склонением. Если не реализовывать склонение, использовать нейтральное
«Всего: 4». Не вводить ручной счётчик.

**Базовый вариант — карточки 4:3:**

- ≥1024 px: четыре колонки, gap 20 px.
- 768–1023 px: три колонки, gap 16 px.
- <768 px: горизонтальная лента, карточка шириной `min(78vw, 320px)`,
  gap 16 px. Следующая карточка частично видна.
- Переполнение разрешено только внутри ленты, никогда на всей странице.
- На мобильном использовать native scroll и `scroll-snap-type: x proximity`;
  не перехватывать жесты. Не скрывать скроллбар принудительно.
- При переходе фокуса Tab к следующей карточке она должна попадать в видимую область.
- При появлении пятой модели desktop-сетка переносит её на следующую строку.
- При 1–3 моделях сохранять ширину колонки; не растягивать одну карточку на экран.

**Состав карточки:**

1. Изображение 4:3 с радиусом 8 px.
2. Через 10 px название, максимум две строки визуально.
3. Через 4 px строка метаданных: материал · первый тег; отсутствующие поля убрать.

Вся карточка — одна ссылка. Название внутри `<h3>`, секция имеет `<h2>`.
Полный title остаётся в DOM и доступном имени, даже если визуально line-clamp.
Длинное название не увеличивает разницу высот: зона названия рассчитана
на две строки. Не добавлять summary, облако тегов, кнопку внутри ссылки,
большую рамку, подложку под весь текст или отдельные бейджи «FHD».

Обложки брать из существующего `cover`, alt — из `coverAlt`.
Сохранять семантику `coverFit`. Для `contain` разрешён исходный светлый фон
изображения: нельзя «убрать белый» фильтром invert или mix-blend-mode,
меняющим цвет предмета. Унификация обложек — отдельная подготовка ассетов.

Hover: изображение увеличивается до 1.025 внутри своего контейнера за 160 ms,
название светлеет; карточка не прыгает и не перекрывает соседей.
Focus-visible: жёлтый outline 2 px с offset 4 px, не обрезанный лентой.
Не показывать важную информацию только при hover.
При `prefers-reduced-motion: reduce` убрать трансформации и плавную прокрутку.

## 8. Компоненты и CSS

Рекомендуемые компоненты:

- `src/components/HomeHero.astro` — текст, фото принтера и CTA.
- `src/components/ModelCard.astro` — карточка, получает модель.
- `src/pages/index.astro` — получение моделей, empty state и композиция секций.

Не создавать универсальную дизайн-систему, карусельную библиотеку или клиентский
state-management. Основная страница работает без JavaScript.

Изолировать селекторы главной: `.home-hero`, `.home-models`, `.model-card`.
Не расширять `.gallery`, `.cover`, `.model-head`, `.specs` ради главной.
При необходимости добавить в Base типизированный prop варианта шапки
с безопасным default для страниц моделей.
Существующие токены `--bg`, `--ink`, `--muted`, `--line` сохраняют имена,
чтобы страницы моделей получили согласованные цвета.

Все внутренние ссылки строить через `import.meta.env.BASE_URL`.
Не использовать `/models/...` и `/` напрямую: проект размещён под
`/print-showcase/`. Новые изображения импортировать через Astro assets.

## 9. Доступность и загрузка

- Один H1 на странице, последовательность H1 → H2 → H3.
- Добавить ссылку пропуска шапки к main, видимую при фокусе.
- Навигация и карточки доступны с клавиатуры, фокус всегда виден.
- Текст не превращать в картинку. CTA различим без наведения.
- Проверить контраст текста: обычный минимум 4.5:1, крупный 3:1.
  Проверять текст hero поверх конечного изображения, а не только CSS-фон.
- У героя `loading="eager"` и `fetchpriority="high"`; у карточек lazy loading.
- Задавать размеры/соотношение сторон изображения, чтобы избежать сдвига вёрстки.
- Использовать responsive widths и sizes, соответствующие фактической ширине.
  Не увеличивать исходник 1000 px ради srcset 2400 px.
- Не добавлять видеофон, тяжёлые зависимости и JS ради градиентов.
- Не ухудшать существующие title, description, canonical, OG и robots-поведение.
- Проверить Telegram-виджет на тёмной странице модели; он не должен ломать
  ширину страницы. Сторонний iframe не перекрашивать CSS-фильтрами.

## 10. Пошаговая работа для исполнителя

Выполнять по одному блоку; после каждого шага проверять его результат.

1. Прочитать CLAUDE.md, эту спецификацию и связанные исходники. Проверить
   git status; не трогать посторонние изменения, `.claude/` и Python cache.
2. Учесть подтверждённые решения: текст + фото принтера в hero, карточки 4:3.
   Получить фото перед финальной визуальной проверкой. Мобильная лента и
   точные тексты пока предлагаются этой спецификацией.
3. Создать `design-tokens.md`. Внести палитру и шрифты, проверить главную
   и одну страницу модели на читаемость.
4. Реализовать шапку. Проверить 360 и 1440 px и длинный текст/перенос.
5. Подготовить фото принтера и импорт. Если фото ещё нет, собрать локальный
   каркас и явно отметить недостающий ассет в отчёте.
6. Сделать только hero. Проверить целостность принтера, переносы H1,
   видимость кнопок, мобильный порядок, переход к фону.
7. Сделать карточку и каталог. Проверить четыре реальных обложки, длинные
   названия, `coverFit: contain`, мобильный скролл и клавиатурный фокус.
8. Проверить страницы моделей: заголовок, specs, фото, lightbox, ссылки на TG,
   условные contact/video; исправить только регрессии общих стилей.
9. Выполнить `npm run build`; проверить собранные ссылки и ассеты
   с учётом `/print-showcase/`.
10. Сделать скриншоты главной 390×844, 768×1024, 1440×900 и страницы модели
    390×844 / 1440×900. Дополнительно проверить 360, 1024, 1920 px без overflow.
11. Предоставить список изменённых файлов, результаты сборки, скриншоты
    и оставшиеся визуальные ограничения. Не утверждать, что браузерная
    проверка выполнена, если проверена только сборка.

Не писать тесты, дублирующие CSS. Для такого изменения достаточно сборки,
проверки крайних случаев данных и реального визуального/клавиатурного прохода.
Если инструмент браузера недоступен, указать невыполненные проверки.

## 11. Критерии готовности

- [ ] При открытии главной видно: почти чёрный фон, жёлтый логотип и CTA,
      крупная фотография принтера справа, текст слева.
- [ ] Hero не выглядит белой картинкой в отдельной рамке; принтер читается,
      корпус и значимые части не обрезаны.
- [ ] В 1440×900 видны изображения и названия каталога без прокрутки.
- [ ] В 390 px hero перестроен в вертикальную композицию, текст не на предмете.
- [ ] Карточки компактные: изображение, название, одна строка метаданных.
- [ ] Все четыре модели доступны, ссылки ведут на соответствующие страницы.
- [ ] Нет фиктивных рейтингов, кнопок плеера, пустых подборок и неработающих иконок.
- [ ] В светлой системной теме сайт остаётся тёмным.
- [ ] Нет горизонтального скролла всей страницы в диапазоне 360–1920 px.
- [ ] При 200% увеличении текст доступен, кнопки не перекрывают друг друга.
- [ ] Tab показывает фокус; все ссылки достижимы, в том числе в мобильной ленте.
- [ ] Пустая коллекция не ломает сборку; draft-модели не показываются.
- [ ] `SITE.contact: ""` не создаёт пустую кнопку.
- [ ] Страницы моделей и OG продолжают работать; тексты историй сохранены.
- [ ] `npm run build` успешен.
- [ ] Пользователь вычитал новые подписи перед публикацией.
