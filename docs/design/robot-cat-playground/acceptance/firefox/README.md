# Firefox local acceptance, 2026-10-29

Firefox Developer Edition 152.0b10, headless through geckodriver 0.36.0, against the local Astro development server. The 390×844 viewport uses a 390-pixel iframe because Firefox's outer window cannot be made that narrow; the other viewport sizes use the browser window. Screenshots are kept here separately from unit tests.

- `normal-motion.json` and `normal-*`: 390×844, 768×1024, 1440×900 and 1920×1080; head/body/mode choices, editor template, drawing persistence and undo, cart controls and exploded state. The instrumented playground bitmap peak was 29,491,200 bytes. This is not browser-wide memory accounting.
- `reduced-motion.json` and `reduced-*`: the same matrix with reduced motion enabled.
- `no-js.json` and `no-js-*`: static fallback, hidden inactive controls, gallery links and no horizontal overflow at the same sizes. `initial-failure.json` and `initial-failure.png` check the same fallback when the first interactive image fails with JavaScript enabled. They also verify that another failed retry restores focus to the retry button and a successful retry activates the scene and focuses it.
- `zoom-200.json` and `zoom-200.png`: native Firefox 200% zoom, 720×450 CSS viewport, controls in document flow and no horizontal overflow.
- `combinations.json`: all twelve combinations selected on the live page, with distinct canvas hashes and matching labels.
- `keyboard.json` and `keyboard.png`: native key activation of head, body, connection, mode, cart and template controls; focused arrows, undo, focus trap and Escape restoration.
- `memory-reporter.json`: Firefox image-cache snapshots plus the controllers’ owned-frame counters, including decode reservations. The measured story sample was 63,112,576 bytes and the held playground transition sample was 49,772,932 bytes when added conservatively; the two categories may overlap. These are targeted snapshots, not a continuous browser-wide peak.
- `interactions.json`, `native-drawing.png` and `native-body-drawing.png`: WebDriver mouse drag, focused arrow key, free drawing and focus restoration, injected network and corrupt-image decode failures with retry, a delayed request superseded by a newer choice, background-tab stopping, reverse scroll and drawing persistence, and resize without overflow. Resource Timing measured a peak of three overlapping story/playground media requests in the latest run, and story frames 48 → 84 → 24 were checked across forward and reverse scrolling; an earlier run reached four before the small fallback images were inlined.

A native drawing screenshot exposed a broad background blend rule that made dark strokes invisible on the body. The rule is now limited to the history canvas; the interaction probe compares screenshots with the drawing shown and hidden and verifies changed pixels inside the frame.

A normal-motion run initially found a negative animation timestamp in the iframe. The controller now anchors its animation clock to its first animation frame, with a regression test. A first reverse-scroll probe stopped inside the 300-pixel prefetch margin; the passing probe scrolls beyond it before checking release.

Remaining acceptance gaps: Chrome has no connected browser integration; Safari is installed but its driver reports that remote automation is disabled. Touch scrolling on a real phone and a continuous browser-wide decoded-memory peak have not been verified by these probes. Firefox headless touch-typed input moved the cart horizontally and left it stationary on a vertical gesture (`interactions-touch.json`). It scrolled neither the playground nor an ordinary scrollable baseline, even with touch events explicitly enabled, so that probe cannot establish mobile panning behavior. The delayed-request check injects delay at the fetch boundary; it is not full network throttling. The local controller tests cover cancellation and slow-load state rules, but are not a substitute for those browser/device checks.
